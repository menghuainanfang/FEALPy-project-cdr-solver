## 1. 物理时间规模与性能设计
- **主演示目标至少30个物理时间步**（例如 t=0到0.60、Δt=0.02，共30次推进与31个时间节点），推荐中型案例 **50–100步**（例如50步Δt=0.02达到t=1.0）。用户可选择10步快预览、30步正式版、60/100步深入版；数字是计划默认值而不是已测试性能。
- 用户要求“可以大型一点”：允许更长运行和更丰富轨迹，但必须设置合理资源保护，特别是 JSON大小、内存、网格质量、单步最大迭代/最大伪时间及失败退出。先低分辨率验证正确性，再扩大nx、物理步数和日志精度；性能和失效率以真实结果决定最后默认规模。
- 运动必须**肉眼可见且不造假**。优先选择随物理时间移动的陡变界面或局部峰值，并明确它来自数值解还是解析时间驱动目标。设计目标沿水平移动/弯曲/周期运动并确保边界与方程一致，让网格跟随移动，而非每步重启。
- 建议最多3组互补场景：①静态时间输入对照（应无伪“物理更新”）；②随时间平移的移动峰/界面（最容易解释）；③真正的2D黏性Burgers非线性解（必须有经过验证的固定网格PDE基线）；资源可控前提下再选AC/CH，不要一次叠加全部PDE造成无法验收。
- 避免每个物理时间步保存100+个BDF内部完整网格坐标导致数百MB JSON。数据可采用轻量分层存储：**每个物理步记录最终解和网格，选定关键物理步记录高精度的内层轨迹和接受步日志**，其他步保存诊断时间序列（s,residual,energy,Δs,min_area）；演示支持按需加载分片 JSON/离线文件的可靠实现。必须能重跑；不要通过动画插值伪造不存在的真实数值状态。

## 2. 三重循环数学与实际执行顺序
以经验证算法为准，不把以下伪代码视为唯一正确算法：
```
for n in range(N_physical_steps):
    time = t[n+1]
    predict / advance PDE solution on current mesh
    for k in range(max_outer_iterations):
        build metric from current numerical solution (or analytical target if DEMO)
        freeze physical configuration and M for this mesh solve
        for j in accepted_BDF_steps_until_stop:
            update computational coordinates ξ(s)
            evaluate frozen-metric equilibrium residual and mesh validity
            stop only if criterion met or explicit resource/time cap
        reconstruct / update physical mesh using valid mapping
        transfer / solve PDE consistently on new mesh
        evaluate PDE–mesh coupling residual, accept / repeat k
    verify step validity, save state, advance n
```
每个 `physical n` 独立归档，至少包含 `t_n,t_{n+1},Δt`、`k_actual,k_max,outer_residual,outer_tol,outer_stop_reason`、每个 `k` 的 `metric_version,inner_stop,first_converged_s,final_s,bdf_accepted_steps,convergence_trace`。要求解释“内层已收敛、外层否”是否是k=1尚未检查、真不满足阈值还是外层迭代次数到上限。绝不把“只做一次外迭代”硬写成“外层不收敛”；如果根本未实现耦合残量则写“未检查/不适用”，不能声称未收敛。
- 用同一连续演化实例证明 `x^{n+1}_{start}=x^n_{final}` （固定参考/重建映射的正确坐标版本需审查），`M^{n+1}` 来源于更新场。比对每个时间节点的网格、度量场和物理解，确认真实变化不是播放器伪效果。
- 对有物理PDE求解的案例，网格移动须遵循正确的ALE/场转移或保守性逻辑；解释边界条件、时间推进法、非线性求解残量与网格速度影响。已验证固定网格数值解 ≠ 已验证移动网格PDE耦合；需要分别测试。
- 对 `AC/CH` 相场，明确能量/质量诊断跟网格能量区分；对 Burgers 不凭网格能量曲线推断方程准确性。

## 3. 网站信息架构（导师应能3分钟看懂）
单独建立「网格随时间演化」演示页，与“研究任务主档”完全分开。推荐上下分区而非一屏塞满：
**页首**：本例一句话问题陈述/方程来源和实验类型标签（“已数值求解Burgers”或“解析随时间目标驱动的网格演示”）；说明“网格为何要跟随正在移动的解/界面”。
**第一屏主视图**：四个同步小图或三图+可切换的场图：
1) 解 `u(x,y,t)` 的色彩场/界面位置（若为解析目标必须写明）；
2) 旧物理网格 `x^n`（浅灰，参照上一物理时刻）；
3) 本步更新后网格 `x^{n+1}`（高亮，可叠加旧网格）；
4) 计算网格 `ξ`（展示内部优化，可选折叠）。
应突出移动目标、网格如何从上一时刻继续适应，而不是同时展示几百条拥挤边线。用可开关的网格抽样、差异颜色、移动热度图、单元质量热图和选中节点位移箭头解释差别。
**第二屏时间轴**：独立、明确的三个控件：
- `物理时间 n/t` 主时间轴，例如“第12/60个物理时间步，t=0.240”，可播放/暂停/逐步，包含关键事件书签；默认主播放此轴。
- `外层 k` 每个物理时间步内选取具体耦合轮次；显示已完成几轮和外循环终止条件。
- `网格内层 j/s` 只在选定(n,k)展开，显示BDF接受步编号、当前伪时间、残量阈值，不能和全局物理时间混为一谈。
所有展示计数从实际数据生成，不能写死61/111等值。
**第三屏诊断区**：应用 P1 面板，展示内层 `r_RMS` 与阈值、首次达标时间、持续达标、伪时间上限状态、最小正有向面积、旧/新网格位移、网格能量epoch；独立标明 `outer_residual/outer_tol` 与PDE非线性残量及求解状态。每一层一条“为什么继续/为什么停止”的解释。
**第四屏解释与学习模式**：提供“从头理解本演示”导览，至少五步：
  (1) t=0初始物理解和网格 → 
  (2) PDE在物理时间推进，解/界面移动 → 
  (3) 根据新场计算新的度量张量M → 
  (4) 在当前M下网格伪时间内迭代，显示第几步与收敛曲线 → 
  (5) 重建/传递物理解、检查外层，进入下一物理时间步。
每一步的说明引用真实当前数值和图示（非AI编造的通用结论）。可在说明浮层写短小公式与术语解释。
**第五屏**：验证/数据来源，FEALPy与项目SHA、参数/种子、网格尺寸、DOFs、数据版本、时间与空间离散、哪些结果为实测、哪些未验证；源码链接和“如何重跑”命令。

## 4. 两种可视化模式：一眼看动态 + 深入看求解
- **故事模式（默认）**：仅物理时间轴，拖动/播放从t=0到结束，实时显示解/界面、M的分布、旧/新物理网格、收敛与数据摘要。预设 5 个有真实变化的事件书签；自动标出某些时间步网格重分布强度上升/下降。
- **算法模式（点击展开）**：当前物理步n→外层k→内层j，任意层可冻结和逐步浏览；应能看到网格伪时间s推进的实际轨迹、残量、步长、停止原因。允许在同一(n,k)下并排展示开始/结束两个网格。
- 点击“?”出现术语词典；点击指标曲线上的数据点定位(n,k,j)。图表应有坐标轴/单位/基准；颜色不能独自承担语义。适应Windows Chrome/Edge桌面浏览器，离线网页应可正常展示；UI不要夹杂项目管理卡片。

## 5. 收敛与解释逻辑必须真实
- 网格内层、耦合外层、PDE数值求解三个判据用独立颜色和文字。状态推荐：`converged`, `cap_reached`, `failed`, `not_checked`, `not_applicable`；别把后两者写成“不收敛”。
- `first_converged_s` 与 `final_s` 分开；在伪时间上限同时满足标准，UI显示“在上限处满足阈值”，而非“提前收敛”。
- 网格冻结能量单调性仅在同一固定度量epoch内适当解释；不可直接连接跨物理时间步的不同能量曲线推断总能量下降。
- 同屏注明：时间 t（PDE物理时间）、s（网格优化伪时间）、wall time（实际运行耗时）互不等价；页面的fps和浏览器播放速度只影响动画。
- 如果旧截图报告 `s=3.0,111 accepted, residual=5.659e-7, outer=否`，新版需要可以通过源码/数据解释s=3.0是否上限、是否达阈值、外层“否”是什么原因，避免只重复没有解释的数字。

## 6. 验收与真实实验
**基础执行**：至少30次真实物理时间推进，输出关键物理时刻 t=0,0.1,0.2,... 的数值状态；附全部物理时步的状态CSV与可复算JSON。推荐60步或更多，但只在数值验证、网格稳定、成本和存储可控的情况下升级。明确说明是物理步数，不是播放帧数。每次物理时步应有n、t、PDE状态/目标更新、metric版本、耦合k、网格j、停止状态和最小单元面积。
**深化版**：50–100物理时步的稳定演示；至少一个明显移动的界面、峰值或过渡层；展示自适应网格与固定网格的直观对比，并进行2档nx/Δt的基本一致性或误差对照。
**科研验证**：回归测试包括：n增加导致目标/解变化；两相邻物理步网格是连续继承的；边界合法、所有展示单元有向面积为正；更改帧数不改变物理推进/网格停止；静态极限正确；时变metric的epoch不会被用于跨期错误能量判断；两层停止判据独立，物理PDE求解失败时不能标“整体成功”。
**性能与工程**：预设10/30/60/100步命令选项，在报告里实测耗时、JSON大小、最大内层迭代、拒绝和失败记录。大数据时改分片/抽样展示，但始终保留重现所需完整状态或足够的原始检查量。不要造出“插值出来的内迭代帧”冒充真实数值轨迹。
**与固定网格PDE教学衔接**：对应单独P0学习任务。最优方案是选固定网格Burgers基线，经过正确离散/误差验证后接网格更新；如在本周仅完成解析时间目标驱动，页面大标题必须明确“教学用时变解析目标网格演示（不求解非线性PDE）”，同时独立陈述尚未完成的真实耦合点。
